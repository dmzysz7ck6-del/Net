# The Migration Network Is Not the Knowledge Network?

A reproducible empirical pipeline comparing three country-level networks:

| Layer | Edge | Source |
|---|---|---|
| Migration | people born in *i* living in *j* (directed stock) | UN DESA International Migrant Stock 2024 |
| Scholarly mobility | inferred moves of publishing scholars *i* → *j* | Akbaritabar, Theile & Zagheni (2024), *Scientific Data* |
| Co-authorship | journal articles with affiliations in both *i* and *j* (undirected) | OpenAlex |

The project asks how closely a country's migrant destinations match its research
partners (RQ1). It asks which country pairs collaborate more or less than geography,
capacity and migration predict (RQ2). It asks whether scholarly mobility carries
information that general migration does not (RQ3), and whether bridging positions
differ across layers (RQ4). It pays particular attention to Sub-Saharan origins (RQ5).
The premise is treated as a falsifiable hypothesis.

## Status

> **No empirical results exist yet.** The execution environment that built this
> repository blocks HTTPS access to every data host (OpenAlex, UN DESA, Zenodo, World
> Bank, CEPII, Crossref). The pipeline, tests, pre-registered analysis plan, literature
> review and methodology are complete. The data acquisition and everything downstream
> of it have **not** been run. Nothing in this repository is simulated research data.
> The synthetic fixtures under `tests/` only check that the code works.

See `research/progress.md` for an exact account of what is done and what remains.

## Layout

```
config/pipeline.yaml      every analytical parameter (windows, filters, thresholds, seeds)
src/acquisition/          cached, logged, resumable downloads (UN DESA, Zenodo, OpenAlex, WDI, CEPII)
src/cleaning/             country crosswalk, parsers, co-authorship counting rules, panel builder
src/networks/             layer construction, strength-preserving nulls, retained metrics
src/analysis/             alignment (H1-H2), PPML gravity (H3-H4), residual pairs, topology, runner
src/visualization/        publication figures (SVG/PNG) and interactive HTML
src/reporting/            data-quality report, claim registry/verification, bibliography tools
research/                 analysis plan (pre-registered), literature review, methodology, progress
tests/                    pytest suite (synthetic fixtures only)
data/raw|interim|processed, outputs/, figures/, blog/   (filled by the pipeline)
```

## Running it

```sh
pip install -e .[test]
cp .env.example .env          # optional: OPENALEX_MAILTO / OPENALEX_API_KEY (never committed)
make test                     # 64 tests, synthetic fixtures only
make check-access             # every host must say "ok"
make pilot                    # four-origin pilot: Somalia, Ethiopia, Kenya, Ghana
make research                 # acquire -> clean -> analyze -> quality -> figures -> verify
make verify-refs              # check bibliography DOIs against Crossref
```

### Network access

In a sandboxed environment, these hosts must be allowed:
- `api.openalex.org`
- `www.un.org`
- `zenodo.org`
- `api.worldbank.org`
- `www.cepii.fr`
- `api.crossref.org` (reference checks)

The pipeline is zero-cost: it stops on HTTP 402 and uses only public endpoints.

## Key documents

- `research/analysis_plan.md`: hypotheses H1–H4, decision rules and robustness checks,
  written before any data were seen. Its SHA-256 is recorded in `research/progress.md`.
- `research/literature_review.md` and `research/bibliography.md`: the closest prior work
  and what this project could add. Each reference carries a verification label.
- `research/methodology.md`: data definitions, estimators, assumptions and limitations.
- `research/data_quality_report.md`: generated by `make quality`.
